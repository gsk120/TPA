# 토비 · 개인비서

텔레그램 비공개 가족 그룹에서 일정과 할 일을 관리하는 개인비서입니다. Node.js 프로그램이 메시지를 수신하고, 필요한 자연어 해석을 Codex CLI에 요청한 뒤 Supabase에 기록하고 결과를 알려줍니다.

## 주요 기능

- 일정·할 일 추가, 변경, 완료 및 날짜별 목록 조회
- 일일·주간 점검과 예약 알림
- 가족 그룹별 데이터와 구성원 구분
- 자연어 후속 대화와 변경 이력 보존
- 명확한 기본 조회는 AI 없이 처리하고, 다양한 표현은 구조화된 조회 범위로 해석
- Windows에서 백그라운드 시작·종료·상태 확인

## 실행 구조

```text
텔레그램 가족 그룹 ↔ Node.js 비서 프로그램 ↔ Supabase
                              ↕
                          Codex CLI
```

현재는 계속 실행되는 프로그램이 텔레그램을 확인하는 폴링 방식입니다. 실행 장비가 꺼지거나 잠자기에 들어가면 수신·점검이 중단됩니다. Cloud Run 웹훅 운영과 macOS 자동 시작은 아직 별도 구성·검증이 필요합니다.

## 준비 사항

- Node.js 22.18 이상과 npm
- 실행 장비에 설치되고 로그인된 Codex CLI
- Supabase PostgreSQL 프로젝트와 전용 애플리케이션 DB 계정
- 텔레그램 BotFather에서 만든 봇과 비공개 가족 그룹

개인 로그인 정보나 토큰을 저장소에 넣지 않습니다. 새 장비에서는 그 장비에서 별도로 CLI 로그인과 환경설정을 구성합니다.

## 최초 설치

프로젝트 폴더에서 다음을 실행합니다.

```powershell
npm ci
npm run setup
```

처음 설정할 때 `.env`와 `data/bootstrap.sql`이 생성됩니다. 기존 `.env`는 덮어쓰지 않습니다. 기존 설정에서 파일이 누락된 경우에는 파일을 임의로 재생성하거나 DB 비밀번호를 변경하지 말고 설치 상태부터 확인합니다.

### DB 준비

신규 프로젝트에만 다음 순서로 적용합니다. 이미 운영 중인 DB는 초기화하지 말고 적용된 변경 내역을 먼저 확인합니다.

1. Supabase SQL Editor에서 `sql/schema.sql` 실행
2. `sql/multi-family.sql`, `sql/allow-flexible-members.sql` 순서로 실행
3. 로컬 `data/bootstrap.sql`로 `assistant_app` 계정 비밀번호 설정
4. Session pooler 연결 정보를 `.env`에 입력

애플리케이션 실행에는 관리자 `postgres` 계정 대신 `assistant_app` 전용 계정을 사용합니다. `data/bootstrap.sql`에는 실제 비밀번호가 들어 있으므로 공유하지 않습니다. DB 변경은 실행 전에 내용을 검토하고 운영 데이터는 별도로 백업합니다.

### 환경설정

`.env.example`에는 빈 설정 양식만 있습니다. 실제 값은 로컬 `.env`에만 작성합니다.

| 항목 | 용도 |
|---|---|
| `DATABASE_URL` | 비밀번호를 포함한 전용 계정 DB 연결 문자열 |
| `DATABASE_CA_FILE` | TLS 검증용 Supabase CA 파일 경로 |
| `TELEGRAM_BOT_TOKEN` | BotFather에서 발급받은 봇 토큰 |
| `CODEX_EXECUTABLE` | CLI 실행 파일 경로. 비우면 `codex` 사용 |
| `CODEX_JS` | Node.js로 실행하는 CLI 진입 파일 경로. 해당 설치 방식에서만 지정 |
| `CODEX_MODEL` | 사용할 모델. 비우면 CLI 기본값 사용 |
| `CODEX_TIMEOUT_SECONDS` | AI 처리 제한 시간. 기본 180초, 허용 범위 10~600초 |
| `MESSAGE_MODE` | `addressed` 사용 |
| `SCHEDULER_ENABLED` | `false`이면 예약 점검 중지 |
| `TELEGRAM_CHAT_ID`, `TELEGRAM_USER_IDS`, `FAMILY_ID` | 기존 자료 도구용 선택 설정. 그룹 등록 정보는 DB로 관리 |

CA 파일 경로는 실행 장비에 맞게 지정하며 TLS 검증을 끄지 않습니다. 모델 지원 여부와 CLI 사용 한도는 로그인된 계정과 설치 버전에 따라 확인해야 합니다.

### 텔레그램 연결

1. 비공개 가족 그룹에 봇을 추가하고 관리자로 등록합니다.
2. 다른 구성원의 소속 확인과 입·퇴장 수신에 필요한 관리자 상태를 유지합니다. 메시지 삭제·사용자 차단 등 불필요한 권한은 부여하지 않습니다.
3. 실행 장비에서 CLI 로그인 후 아래 점검을 실행합니다.

```powershell
npm run doctor
npm run bot:start
```

4. 그룹 관리자가 가족방에서 `/setup`을 보냅니다.

일반 가족 대화 전체를 AI에 보내지 않습니다. `!`로 시작하는 메시지, 봇 멘션·답장 및 지원 명령으로 요청합니다. 동일한 봇 토큰을 사용하는 운영 프로그램을 여러 장비에서 동시에 실행하지 않습니다. 장비를 옮길 때 기존 장비를 먼저 종료합니다.

## 사용 예시

```text
!전체 일정 보여줘
!치과 예약 12월 5일 오전 9시 30분 추가해줘
!스냅 예약 내일로 바꿔줘
!스냅 예약 완료했어
!매일 알림 오전 7시 반으로 바꿔줘
```

| 명령 | 기능 |
|---|---|
| `/today` | 오늘 일정·할 일과 점검 |
| `/week` | 앞으로 7일 |
| `/list` | 남은 전체 목록 |
| `/settings` | 현재 일일·주간 알림 설정 조회 |
| `/help` | 사용법 |

`/setup`은 그룹 관리자용 가족 연결·복구 명령입니다. 일정 갱신, 상세 조회, 과거 분석, 알림 변경은 자연어로 요청합니다. 애매한 요청에는 확인이 필요하며, 미응답을 완료로 간주하지 않습니다.

## 운영

macOS에서 수동으로 운영하는 경우 [macOS 수동 운영 안내](MACOS-MANUAL.md)를 참고합니다.
프로젝트 전용 `./tpa start / stop / restart / status / logs / follow` 실행기가 기존 npm 명령을 사용하며,
시스템 Node나 셸 설정은 변경하지 않습니다. Windows 봇을 종료하고 전환을 승인하기 전에는 Mac 봇을 시작하지 않습니다.

```powershell
npm run bot:start
npm run bot:status
npm run bot:logs
npm run bot:restart
npm run bot:stop
```

Windows에서 `npm` 실행 정책 오류가 나면 `npm.cmd`를 사용합니다. 백그라운드 실행은 터미널을 닫아도 유지되지만, 컴퓨터 재부팅 후 자동 시작을 등록하는 기능은 포함하지 않습니다.

`npm start`는 터미널에서 직접 실행하며 `Ctrl+C`로 종료합니다. 백그라운드 프로그램과 동시에 켜지 않습니다. 코드를 갱신한 뒤에는 재시작해야 적용됩니다. 로그에는 개인 데이터가 섞일 가능성이 있으므로 원문을 공개하지 않습니다.

## 검증과 백업

```powershell
npm test
npm run doctor
npm run backup
```

- 테스트에는 임시 DB와 백그라운드 테스트 프로세스가 포함됩니다. 테스트 성공은 실제 CLI 로그인·텔레그램 발송 성공을 의미하지 않습니다.
- `doctor`는 실제 설정으로 연결 상태를 점검합니다.
- `backup`은 기존 자료 도구용 가족 설정을 사용하므로 해당 `FAMILY_ID` 등 설정을 확인한 뒤 실행합니다. 결과는 `data/backups/`에 저장되며 모든 가족 전체 백업으로 간주하지 않습니다.
- 백업에는 개인 일정·이력이 포함됩니다. Git과 분리된 안전한 위치에 별도로 보관합니다.

## 저장소에 포함하는 파일과 제외하는 파일

공유 대상은 `src/`, `test/`, 비밀번호 없는 `sql/`, `package.json`, `package-lock.json`, `.env.example`, `.gitignore`, 이 README입니다.

`.gitignore`는 다음을 제외합니다.

- 실제 환경설정, CLI 인증 캐시, 서비스 계정·개인키·인증서 파일
- `data/` 전체: 생성된 비밀번호 SQL, 실행 상태, 로그와 백업
- 개인 일정·가족 정보가 담긴 로컬 `PRD.md`, 과업·이력 파일과 내보내기 폴더
- 의존성, 에디터 설정, 임시 복사본, 압축 파일 및 개인 첨부자료

CA 인증서 자체는 공개 자료일 수 있지만 이 프로젝트에서는 인증 파일을 일괄 제외합니다. 필요한 CA는 실행 장비에 별도로 준비합니다. 개인 PRD는 저장소에서 제외되므로 새 장비로 옮길 때도 별도 관리합니다.

### 최초 업로드 전 확인

1. 업로드 변경 목록에 `.env.example`만 있고 실제 `.env`가 없는지 확인합니다.
2. `data/`, `PRD.md`, 인증 파일, 로그·백업·개인 첨부자료가 없는지 확인합니다.
3. 공유할 소스·SQL·테스트에 토큰, 비밀번호, 연결 문자열, 실제 가족 기록을 직접 적어 넣지 않았는지 확인합니다.
4. 원격 저장소는 우선 비공개로 운영하는 것을 권장합니다.

`.gitignore`는 이미 추적되거나 과거 커밋에 포함된 파일을 제거하지 않으며 강제 추가도 막지 못합니다. 이미 올라간 비밀값은 파일 삭제만으로 해결되지 않습니다. 토큰·비밀번호를 교체하고 추적 목록 및 과거 이력을 별도로 정리해야 합니다. 파일 내용의 비밀값까지 자동 탐지하는 장치는 아니므로 업로드 변경 목록 검토가 필요합니다.

이 프로젝트의 개발 규칙상 Git 초기화·추적 해제·커밋·브랜치·푸시는 사용자가 직접 수행합니다.
